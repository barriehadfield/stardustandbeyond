# CLAUDE.md — Stardush site

Static, image-first portfolio website. Served as a **static GitHub Pages site from
the repo root**. Plain HTML/CSS/JS — no framework, no runtime deps. Scaffolded from
the `henridavies` template.

Design: a single **dark charcoal** identity (no light theme), **coral** accent/CTA
(`#ff6f49`), image-first galleries where each image sits "raised" on the surface, a
landing home page, and a full-screen **swipe + pinch-zoom** lightbox.

## Placeholders to replace

This is a fresh scaffold. Before launch, set real values for:

- **`SITE`** in `scripts/site-data.mjs` — `name`, `role`, `url` (live domain, no trailing slash).
- **`SOCIAL`** in `scripts/site-data.mjs` — Instagram / Bluesky URLs (empty ones are omitted from the page).
- **`CNAME`** — not present yet; create it with the custom domain when ready.
- **`source/og-card.html`** — share-card copy + cover image still say "Stardush" / `cover.jpg`.

## Mental model

Three layers — you almost never hand-edit the middle or bottom one:

```
DATA (edit this)              →  BUILD (scripts)     →  OUTPUT (committed, don't hand-edit)
scripts/site-data.mjs             npm run build          index.html, paintings.html, …
source/images/<section>/*         npm run optimize       public/images/<section>/*
```

- **`scripts/site-data.mjs`** — the single source of truth for content
  (`SITE`, `SOCIAL`, `PAINTINGS`, `PHOTOGRAPHY`, `FASHION`, `INTERIORS`, `ABOUT_PARAS`, `FOR_SALE`).
- **`source/images/`** — full-resolution originals (archive). Committed on purpose.
- **`public/images/`** — web derivatives generated from `source/`. **Generated —
  do not edit by hand.** Regenerate with `npm run optimize`.
- **`*.html` at repo root** — the actual pages. **Generated by
  `scripts/build-pages.mjs` — do not hand-edit.** Edit the data and run `npm run build`.
- **`css/style.css`, `js/site.js`** — hand-written, the real site assets.

## Pages

`index.html` (landing — hero + section cards) · `paintings.html` · `photography.html`
· `fashion.html` (article-led) · `interiors.html` · `for-sale.html` · `about.html`.

The build is **robust to empty data**: on a fresh scaffold every page still builds
(empty galleries; the home hero uses the first available section image, or falls back
to copy only). The home "rooms" grid is driven by the `SECTIONS` registry in
`build-pages.mjs` — each card's cover is the first item of its array.

## Commands

```bash
npm install        # once — installs sharp (build-time only, a devDependency)
npm run optimize   # source/images/**  ->  public/images/**  (after adding/replacing originals)
npm run build      # regenerate all root *.html from build-pages.mjs
npm run dev        # no-cache static server at http://localhost:8000
```

**Serve with `npm run dev`, not `python3 -m http.server`.** `scripts/dev-serve.py`
sends `no-store` headers so a normal browser refresh always shows freshly built
files; the plain server lets the browser cache css/js and "changes don't show".

There is **no test suite**. "Verify" = build, serve, and screenshot with headless
Chrome. Headless Chrome enforces a **~500px minimum viewport**, so use
`--window-size=600,…` (still under the 720px mobile breakpoint) for mobile shots.

## Image pipeline (`scripts/optimize-images.mjs`)

For every original in `source/images/{paintings,photography,fashion,interiors,site}/`
it emits four files into the matching `public/images/…` folder:

| file | purpose |
|------|---------|
| `<name>.webp` / `<name>.jpg`             | full-size (max edge 2000px), webp + jpeg fallback |
| `<name>-thumb.webp` / `<name>-thumb.jpg` | gallery thumbnail (max edge 800px) |

- To add a new section folder, add its name to the `SUBDIRS` array.
- EXIF orientation is respected; originals are never modified.

## Page generator (`scripts/build-pages.mjs`)

Builds every page from a shared `layout()` + the data imported from `site-data.mjs`:

- `NAV` — top nav. Wordmark → home. Brand text comes from `SITE.name`.
- Each gallery item is `{ file, title? }`; `title` optional (untitled → no caption,
  generic alt). **Array order = display order.** Append new works to the arrays.
- `dims()` reads width/height from the `-thumb.jpg` so every `<img>` gets
  `width`/`height` → no layout shift.
- `tile()` → `<a class="tile" … data-full="…webp" data-title="…">`. **The lightbox
  in `js/site.js` collects `.tile[data-full]` in document order**, so any
  lightbox-able image must use that shape; the sequence is the swipe order.
- Tiles need `data-pswp-width`/`data-pswp-height` (the **full**-image dims —
  `fullDims()` reads them from `<file>.jpg`); `data-title` becomes the caption.

## Conventions & gotchas

- **Relative asset paths** (`public/images/…`, `css/…`) — required because Pages
  may serve the project under a subpath. Never use root-absolute `/…` paths.
- **No em-dashes** in visible copy (user preference); **UK spelling**.
- `.nojekyll` is present so Pages serves files as-is.
- Portrait for the About page + JSON-LD is expected at `public/images/site/portrait.jpg`;
  the favicon/logo at `public/images/site/logo.jpg`.
- To update PhotoSwipe: `npm i -D photoswipe@x` then re-copy
  `dist/{photoswipe.esm.js,photoswipe-lightbox.esm.js,photoswipe.css}` into `js/vendor/photoswipe/`.

## Deploying

GitHub Pages → Settings → Pages → Deploy from branch → `main` / root. Add a `CNAME`
file with the custom domain and point DNS at Pages. Commit the generated `*.html`
and `public/` — they are what Pages serves.

**SEO** is generated in `layout()` from `SITE.url`: each page gets a canonical URL,
per-page `<meta description>`, Open Graph + Twitter card tags with a representative
absolute `og:image`, and the home page carries a `WebSite`/`Person` JSON-LD block
whose `sameAs` are the non-empty `SOCIAL` links. `npm run build` also writes
`sitemap.xml` and `robots.txt`. If the domain changes, update `SITE.url` and rebuild.

The **share card** (`DEFAULT_OG_IMAGE` → `public/images/site/og-card.jpg`) is a
dedicated 1200×630 image. Its design source is `source/og-card.html`; render it to
`public/images/site/og-card.jpg` with headless Chrome — see the comment at the top of
that file. It is **not** produced by `npm run optimize`.
