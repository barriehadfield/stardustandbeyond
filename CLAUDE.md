# CLAUDE.md — Stardust & Beyond

Static, image-first photo-archive website for **The Stardust** — a 1970s Durban
disco — and the friends who lived it, kept across four decades. Served as a
**static GitHub Pages site from the repo root**. Plain HTML/CSS/JS — no framework,
no runtime deps. Scaffolded from the `henridavies` template; content imported from
a Google-Docs export (see below).

Design: a **1970s disco** identity — deep-aubergine night ground, **gold** (`#f4b740`)
primary accent + **hot-magenta** (`#ff4fa3`) secondary, a soft dance-floor glow, a
serif display wordmark, image-first galleries on "raised" surfaces, and a full-screen
**swipe + pinch-zoom** lightbox. Tasteful retro — the photographs stay the star.

## Content origin

Content comes from a Google-Docs `.docx` export via **`scripts/import-docx.py`**
(a `.docx` is a zip: seven `sz=52` headings = the sections/tabs, each image's
`descr` alt-text = the photo caption, the first uncaptioned image under "The
Stardust" = the club `LEAD`; a photo may appear in more than one tab, exact
same-tab repeats are skipped; `Aydee`/`Adee` are normalised to `Adi`). **Image
names are content-stable:** an image whose bytes already exist in `source/images/`
keeps its current filename even when a fresh export renumbers everything, so
file-keyed data (the people overrides) survives a re-import; only genuinely new
photos get new names. It copies each embedded image into `source/images/<slug>/`
and regenerates
`scripts/site-data.mjs` (preserving the hand-written `STARDUST_TEXT` /
`BOUDOIR_TEXT` intros). The raw `.docx` (and any earlier HTML export folder) are
**gitignored** (large, redundant with `source/images/`).

**Re-import after the doc changes:** download it as `.docx` into `source/`, then

```bash
python3 scripts/import-docx.py "source/Stardust and Beyond.docx"          # dry-run: prints per-tab counts
python3 scripts/import-docx.py "source/Stardust and Beyond.docx" --apply  # rewrites source/images + site-data.mjs
npm run optimize && npm run build
```

## Mental model

```
DATA (edit this)              →  BUILD (scripts)     →  OUTPUT (committed, don't hand-edit)
scripts/site-data.mjs             npm run build          index.html, the-stardust.html, …
source/images/<slug>/*            npm run optimize       public/images/<slug>/*
```

- **`scripts/site-data.mjs`** — single source of truth: `SITE`, `SOCIAL`
  (`instagram` / `bluesky` / `whatsapp`; empty ones are omitted), `LEAD` (the club
  photo), `SECTIONS` (the tab registry), the `STARDUST_TEXT` / `BOUDOIR_TEXT` intros,
  and one gallery array per section, aggregated into `GALLERIES`. Each item is
  `{ file, title? }`; `title` is the caption. Array order = display order.
- **`source/images/`** — full-resolution originals (archive), one folder per section.
- **`public/images/`** — web derivatives. **Generated — do not edit by hand.**
- **`*.html` at repo root** — the pages. **Generated by `scripts/build-pages.mjs`.**
- **`source/people.md`** — the **People** master index (hand-edited, allow-list +
  per-photo overrides). Single source of truth for the People tab; the importer
  never touches it. See **People index** below.
- **`css/style.css`, `js/site.js`, `js/gallery.js`, `js/person.js`** — hand-written,
  the real site assets. `js/gallery.js` holds the shared masonry + PhotoSwipe init
  used by both `site.js` (section pages) and `js/person.js` (the People detail page).

## Pages & sections

`index.html` (landing — club hero + section cards) and one page per tab:
`the-stardust.html` · `the-boudoir.html` · `steven.html` · `70s.html` · `80s.html`
· `90s.html` · `2000.html`, plus `people.html` (the People index) and `person.html`
(the JS-driven per-person view). Nav, home "rooms" grid, and page builders are all
driven by the `SECTIONS` array (People is appended to the nav separately; it is not
a photo section). `LEAD` (`the-stardust/image861`, the uncaptioned club photo) is
the site's hero on the home page and a glowing lead figure atop the Stardust page.
The Stardust page opens with `STARDUST_TEXT`, the Boudoir page with `BOUDOIR_TEXT`
(section intros are wired via `SECTION_TEXT` in `build-pages.mjs`). Every page also
carries a WhatsApp "Join the group" nav item and a footer button, from
`SOCIAL.whatsapp`.

## People index

The **People** tab is built from `source/people.md` (the master index), matched
against the photo captions by `scripts/people.mjs` during `npm run build`.

- **`source/people.md`** — hand-edited, editable on GitHub. Two markdown tables:
  a **Roster** (`Name | Aliases | Primary`) and per-photo **Overrides**
  (`Section | File | People`). It is an **allow-list** — only rostered people become
  links, so caption noise (place/event names) is ignored automatically. `Aliases`
  (`;`-separated) merge spelling variants/nicknames into one person; `Primary` picks
  the default person for a first name shared by several people. An override row gives
  the definitive people for one photo (replaces auto-matching). **The importer never
  rewrites this file**, so corrections survive a re-import.
- **Ambiguous bare names are resolved probabilistically.** When a caption's bare first
  name is shared by several roster people, `computePeople` picks the candidate who most
  co-occurs with the photo's *confidently* identified people (full names, unique first
  names, overrides) **within the same section/decade** (overrides act as training
  signal); it falls back to `Primary`, then leaves it unresolved. The report lists every
  co-occurrence resolution to spot-check, plus **people without a surname** and who they
  are most often pictured with, to help identify and surname them.
- **`scripts/people.mjs`** — `parsePeopleMd()` + `computePeople()` (the matcher) +
  a `--draft` mode (`npm run people:draft`) that lists candidate names from captions
  to seed the roster.
- **Build outputs:** `public/people.json` (per-person photos + dims, consumed by
  `js/person.js`), `people.html` (static A-Z index by first name), `person.html`
  (JS shell; `person.html?p=<slug>` shows one person's photos grouped by section),
  and `scripts/people-report.md` (**gitignored, review-only**) listing unresolved
  ambiguous photos (with live image URLs), shared first names, and unmatched tokens.
- **Curation loop:** `npm run build`, read `scripts/people-report.md`, then resolve
  each ambiguous/unmatched case by editing `source/people.md` (add an override, set a
  `Primary`, add an alias, or add a missing person) and rebuild.

### Corrections console (local tool)

A browser tool for gathering fixes without hand-editing markdown. It's local-only
(`corrections.html` carries `noindex`, isn't linked from the site, and its data file
is gitignored).

- `corrections.html` + `js/corrections.js` — the UI: **Photos** tab edits who's in each
  shot (→ overrides), **People & names** tab renames / merges / removes / adds roster
  entries (e.g. add a missing surname), **Export** tab produces a corrections file.
  Work persists in `localStorage`.
- `public/editor-data.json` — the tool's data (photo→people, roster, sections), written
  by `scripts/build-editor.mjs` on every `npm run build` (or `npm run editor`). Gitignored.
- **Round trip:** open `http://localhost:8000/corrections.html` (after `npm run dev`),
  make fixes, Export → **Copy** or **Download** `stardust-corrections.json`. Apply it with
  `node scripts/apply-corrections.mjs <file>` (dry-run) then `--apply` — it rewrites the
  Roster + Overrides tables in `source/people.md` in place. Then `npm run build`.

## Commands

```bash
npm install        # once — installs sharp (build-time only, a devDependency)
npm run optimize   # source/images/**  ->  public/images/**  (after adding/replacing originals)
npm run build      # regenerate all root *.html + the People index from build-pages.mjs
npm run people:draft # print candidate names from captions (to seed source/people.md)
npm run favicon    # source/images/site/favicon.svg -> public/images/site/{favicon.svg,icon-32,icon-180}
npm run dev        # no-cache static server at http://localhost:8000
```

**Serve with `npm run dev`, not `python3 -m http.server`** — `scripts/dev-serve.py`
sends `no-store` so refreshes always show freshly built files. If port 8000 is busy,
run `python3 scripts/dev-serve.py <port> .` directly.

No test suite. "Verify" = build, serve, screenshot with headless Chrome. Headless
Chrome enforces a ~500px minimum viewport — use `--window-size=600,…` for mobile.

## Image pipeline (`scripts/optimize-images.mjs`)

For every original in `source/images/<slug>/` it emits four files into the matching
`public/images/<slug>/` folder: `<name>.webp` / `<name>.jpg` (full, max edge 2000px)
and `<name>-thumb.webp` / `<name>-thumb.jpg` (max edge 800px). Section folders are the
`SUBDIRS` array (the seven slugs + `site`). EXIF orientation respected; originals never modified.

## Adding / changing content

- **Bulk update from the doc** (many photos/captions, moves between tabs, a new tab):
  re-run `scripts/import-docx.py` — see **Content origin** above. It rewrites
  `source/images/` and `site-data.mjs` wholesale.
- **Single new photo (by hand):** drop the original into `source/images/<slug>/`,
  `npm run optimize`, add `{ file: "name", title: "caption" }` to the matching array
  in `site-data.mjs`, `npm run build`.
- **Caption / order / blurb / tagline:** edit `site-data.mjs`, `npm run build`.
  (The home hero tagline is in `buildHome()` in `build-pages.mjs`.)
- **People (names, merges, who's in a photo):** edit `source/people.md`, `npm run
  build`. See **People index** above.
- **New section (tab):** add a slug folder under `source/images/`, add it to
  `SUBDIRS` in `optimize-images.mjs`, add an entry to `SECTIONS` + a gallery array +
  a `GALLERIES` key in `site-data.mjs` (also to `VARMAP`/`BLURB` in
  `import-docx.py` if it should survive re-import), optimize, build.

## Conventions & gotchas

- **Relative asset paths** only (`public/images/…`, `css/…`) — never root-absolute `/…`.
- **No em-dashes** in visible copy (user preference); **UK spelling**. The importer
  already replaced dashes in captions with hyphens.
- `.nojekyll` is present so Pages serves files as-is.
- Palette + glow are CSS custom properties at the top of `style.css` — retune globally there.
- Lightbox is PhotoSwipe v5, vendored at `js/vendor/photoswipe/` (no CDN). Tiles carry
  `data-pswp-width`/`data-pswp-height` (full-image dims) and `data-title` (caption).

## Deploying

GitHub Pages → Settings → Pages → Deploy from branch → `main` / root. Add a `CNAME`
and point DNS at Pages. Commit the generated `*.html` and `public/`. SEO (canonical,
description, OG/Twitter, home-page `WebSite` JSON-LD, `sitemap.xml`, `robots.txt`) is
generated from `SITE.url`; if the domain changes, update it and rebuild.
